# Источники: типы и настройка

Источник добавляется на странице «Источники» (или через БД напрямую для
продвинутых сценариев). Каждый источник — это `type` + `config` (JSON) +
`category`/`priority` (влияют на ранжирование, но не на сбор).

## `rss` — RSS/Atom

```json
{"url": "https://example.com/feed.xml"}
```
Парсинг через `feedparser`, HTML в описании чистится, дата берётся из
`published`/`updated`. Список кандидатов в реальные RU/EN источники — в
README (раздел «Быстрый старт»).

## `website` — листинг сайта (best-effort)

```json
{
  "url": "https://example.com/news/",
  "item_selector": "article, .post, li",
  "link_selector": "a",
  "title_selector": null,
  "excerpt_selector": null
}
```
Даёт заголовок + ссылку + тизер прямо со страницы листинга (без захода на
саму статью — это осознанное ограничение, см. `docs/limitations` в README).
Для полного текста статьи предпочтителен `rss` или `dataset`/`proxy`.

## `telegram` — публичный веб-просмотр канала

```json
{"channel": "some_public_channel"}
```
Читает `https://t.me/s/<channel>` — публичная HTML-версия без токена
Bot API. Работает только для каналов с включённым публичным просмотром.

## `dataset` — датасет организаторов (JSON/CSV)

```json
{
  "path": "articles_sample.json",
  "format": "json",
  "items_path": "data.items",
  "field_map": {"id": "id", "url": "link", "title": "headline", "text": "body", "date": "published", "language": "lang"}
}
```
`path` — относительно `data/fixtures/`; файлы вне этой папки не читаются. Если
`field_map` не задан, адаптер сам пробует стандартные имена полей
(`url`/`link`, `title`/`headline`, `text`/`body`/`summary`, ...). Это
основной способ подключить датасеты, которые предоставят организаторы
хакатона.

## `proxy` — произвольный HTTP/JSON API

```json
{
  "endpoint": "https://partner.example.com/api/news",
  "method": "GET",
  "headers": {"Authorization": "Bearer ..."},
  "items_path": "items",
  "field_map": {"url": "link", "title": "headline", "text": "body"}
}
```
Единый адаптер под любой формат: закрытые API организаторов, партнёрские
фиды и т.п. — конфигурация задаёт, где в ответе искать список статей и как
называются поля. Ничего не хардкодится в коде под конкретный API.

## Защита от SSRF

`website` и `proxy` принимают произвольный URL/endpoint от того, кто
настраивает источник — это по конструкции открытая дверь для запроса любого
адреса. Перед каждым запросом (`app/sources/safety.py`) сервис:
- разрешает только схемы `http`/`https`;
- резолвит хост и отклоняет адреса, не являющиеся публичными (loopback,
  частные диапазоны, link-local/метаданные облака типа `169.254.169.254`,
  multicast, reserved);
- повторяет ту же проверку для конечного URL после редиректов.
Источник с таким адресом просто падает в `Источники` со статусом `error` и
текстом причины — сервис не используется как прокси во внутреннюю сеть.

## Дедупликация и доверие к источнику

- `priority` (по умолчанию 1.0) — вес доверия к источнику, участвует в
  скоринге («доверие к источнику» в блоке «почему выбрано»). Государственные
  бюллетени/регуляторы стоит ставить выше (1.2–1.4), нишевые
  Telegram-каналы — ниже (0.7–0.9).
- `category` — свободный текст (`vendor`/`media`/`government`/`community`/
  `research`), используется только для отчёта по охвату на странице
  «Метрики» — намеренно не смешивается со скорингом, чтобы не задваивать
  влияние.
- Не стройте корпус из одних вендорских блогов — это смещает выдачу к
  маркетингу; полезно мешать государственные бюллетени, независимую
  журналистику и исследовательские источники, как сделано в демо-корпусе
  (`data/fixtures/articles_sample.json`).
